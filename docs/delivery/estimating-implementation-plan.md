E5 need not block a simple manual quote or the first non-configured handover. Implementation scope may be split further when evidence shows a reviewable boundary; preserve the same outcomes and parent traceability.

## 2. E1 exact boundary

Proposed inclusion: one permitted existing opportunity and its fixed company; one accountable estimator; manual included scope/exclusions/assumptions; one defined-supply option; typed product/labour/freight lines with source/date/unit; AUD excluding tax, no tax calculation; explicit unit cost/sell and declared decimal rounding; save/discard, immutable predecessor snapshots and change reason; exact saved-version draft quotation preview/PDF; reuse Opportunity follow-up without changing CRM stage or forecast. Support include/print on draft quote with reconciled grouped hidden amounts if accepted for E1. If that exceeds the first bounded design, keep all lines included/printed and document the deferral explicitly before coding; never silently ship a misleading total.

Excluded: general route/questionnaire engine, multiple alternatives, live catalogue/FX, supplier imports, invented margins/discount thresholds, formal approvals, issue/distribution, customer acceptance/signature, MYOB writes, stock reservation, Finance totals, offline estimating, AI pricing and production migration. A generated draft does not fulfil the later controlled OUT-06 issue obligation.

Definition of ready: actor/outcome/source scope and failure paths agreed; E1 arithmetic convention explicitly selected as synthetic; current main contracts and migration/ADR slots inspected; quote draft customer-safe projection/output retention defined; database/API/browser/restart acceptance identified. The [starter](estimating-first-increment-starter.md) is ready for later invocation but supplies no present implementation authority.

## 3. Handover and acceptance

Each increment uses a dedicated branch/PR, forward-only migration if needed, exact command/runtime evidence, relevant failure/retry/permission tests, visual inspection and durable publication record. Run maintained foundation/prototype/naming checks and required application gates. Never change old migrations, source snapshots or original operation hashes to make new tests pass. Document actual head/merge/main results only after observation.

D-009/D-010 do not close because a synthetic slice works. Accepted production formulas, policies, output templates and operational handovers remain distinct evidence. The first complete estimating domain is not claimed by a polished costing grid. The next task after this design is owner review of the synthetic example and explicit E1 scope/sequencing, followed by E1 only when authorised.
