How the build order works

#001–007: verify and retain the seven existing foundations. These are baseline checks, not rebuild tasks. Recheck them as dependent workflows change.

#008–144: the active queue combines all 37 refinements with all 100 new workflows. Every listed prerequisite appears before the task it supports. Ranks are recommendations; they are not effort estimates, release dates or proof that a task is ready to start.

#145–150: six conditional ideas, subject to a separate scope decision. Excluded from the active queue.

The original register dependencies are distinguished from additional recommended prerequisites in each detail panel. Tasks without a dependency relationship can be worked in parallel if resources allow. Apply relevant access, retention, quality checks, theme conformance and help content throughout; the final adoption phase consolidates whole-app coverage.

Each app URL inherits its earliest outstanding scope rank, or a baseline verification step. Several addresses can share a rank because one task can refine multiple pages. Source implementation statuses and saved review notes are retained.
