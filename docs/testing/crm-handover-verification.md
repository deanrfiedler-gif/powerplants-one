## Fixture and result contract

Use one synthetic company A, organisation, site and active affiliated contact; same-name company B context; an Enquiry and an already Qualified opportunity without a contact. Alex and Casey are proposed eligible sales actors with explicit scoped grants; Jordan owns a separate next Activity. These display names are illustrative, not claims about seeded profiles. Add inactive, Systems, unassigned, read-only, other-workspace, other-company, exact-site and wrong-site identities. Add one required Activity with an extra unreadable target and one historical unrelated restricted Activity. Never create operational users or grants.

Capture complete before/after Opportunity and Activity values, original events, identities/reference counters, origin rows, operation/audit/outbox receipts and P09/P10/E1 linked state/hashes. Count actual committed effects, not returned promises alone. Competing DB cases use independent PostgreSQL backends, observed lock contention/barriers and both serial orderings. No sleeps that merely assume a winner. HTTP cases use real routes/session cookies and injected response loss after a committed effect. Browser proof uses the actual application only after implementation, at 1440×1000, 390×844 and 320px width, with natural long-content reflow.

## Required regression and publication evidence

Run current foundation/prototype/naming/design checks plus all accepted application DB/HTTP/browser/restart suites and E1's independent exact-output restart workflow. At this design baseline the accepted complete application inventory is 434 unique cases (20 unit, 295 DB, 23 HTTP, 96 browser); focused repeats are additional executions, not additional unique cases. Future inventory must include every newer accepted P11+ case, not freeze at 434 or remove an owner guard test without replacing its exact integrity obligation. An old test that rejects all owner changes needs an explicit authorised-transfer counterpart while still rejecting arbitrary SQL/HTTP changes.

Record source head, executed checkout/tree, runtime versions, fresh/upgrade baseline, fixture IDs, actual executed commands and counts, observed competing results, distinct process IDs and PostgreSQL start times, original screenshot hashes/viewports and receipt/output hashes. Record failed/cancelled/skipped gates as such. Review loaded, conflict, unknown-response, denied and long-content desktop/phone originals; static design illustrations do not substitute. Retain all prior immutable source bytes and all 78 parent requirement identities.
