This is an agent implementation decision under the standing order. The three proof corrections resolve the [released handover](https://github.com/deanrfiedler-gif/powerplants-one/pull/865#issuecomment-6686253174); they are not recorded as Dean's decisions. No merge, deployment or operational authority is included.

## Design and authority

[review-pages.ts](../../../../src/engineering/changes/review-pages.ts) creates one request-local reader. Every listed package, including empty packages, goes through unchanged `changesAccess` and `engineeringRow`. The existing 50-entry batching adapter combines these lookups; it does not remove package, customer, site or linked-record visibility checks. `pagePermissionReads` reuses only the exact native scoped permission query. A second exact-SQL memo reuses the duty query with its workspace, actor, capability set, company and site parameters. Both retain active-user and grant-time predicates, and neither survives the request. Policy selection remains the native per-company/per-site version lookup.

After access succeeds, five `ANY(uuid[])` queries read changes, current revisions, reviews, handovers and submissions. Assembly follows package page order, change number, then the native review/return/handover sequence. Review and receiver actionability still use `policyAllows`; returned work still uses the existing edit flag and owner fields. A returned task remains kind `Review`, with `returned=true`.

`frame`, `changesAccess`, `loadSources`, `loadPackageChanges` and `changeReviewTasks` are unchanged. The list read does not need source assessments, commercial data, retests or overlap calculations to project review tasks. Their omitted queries contain no additional escaping package 403/404 guard: access runs before them, and overlap discovery catches other-package refusals as restricted dependencies. No empty package bypasses access. The new reader settles every access call, then rethrows the first failure in package order. The unchanged domain catch discards all Engineering items for that domain, mapping 403 to `denied` and other errors, including 404, to `unavailable`.

[reviewSources](../../../../src/reviews/service.ts) retains the list limit of 50, cursor progression and `!!cursor && count >= 200` bound. Equipment and Customers & sites are unchanged. No API shape, migration, capability, production grant or dependency changes.

For every non-null company filter, Engineering remains `unavailable` and `listWorkReviews` throws `AppError(503, "ReviewSourceUnavailable", "A review source could not be checked. Fixing this is out of scope and needs a separate PR with its own authority review and tests.

## Service and Finance decision

Both remain per-row. `reportReviewTask` owns a transaction and rechecks report/appointment/field authority. `readFinance` owns a transaction and rechecks retained source/account evidence as well as read capabilities. Neither accepts the query client used by the Engineering adapter. Changing those boundaries would require a distinct reader design and a stronger retained-evidence fixture, rather than the same mechanical extraction. The unchanged Service/Finance output participates in the full-result oracle; the Draft skip, 500-selected-item bound, ordering and actionable rules are unchanged. Their measured statement counts are known remaining limits.
