### Known limit: weekly read cost

The full dispatch gate is still evaluated separately for each eligible unstarted Proposed/Confirmed visit; hiding Proposed visits from the attention presentation does not alter gate evaluation. On the freshly reset synthetic coordinator fixture for 22–28 September 2031 (Australia/Brisbane), **10 visits/week**, all eligible and all returning gate evidence, required **669 SQL reads** per weekly response. After one warm-up (779.43 ms), five sequential reads took **595.25, 586.14, 496.83, 468.93 and 531.48 ms**: median **531.48 ms**, range **468.93–595.25 ms**. [Raw samples and method](read-cost-2026-11-05.json).

Measured on this cloud environment with Node 24.21.0 and PostgreSQL 16.15. The probe ran `scheduleSnapshot` through `transaction` at repeatable-read isolation, counted delegated query calls, and timed acquisition through commit; counts exclude BEGIN, SET TRANSACTION and COMMIT. Seed reset and principal creation were outside the timer; no database suite ran concurrently. `src/scheduling/planner.ts` is unchanged from the merge-only commit. These are complete weekly-read measurements, not an isolated gate benchmark or a larger-week/load/hosted performance claim. Per-visit amplification remains a known limit; no authority, gate rule or cache changes are claimed.
