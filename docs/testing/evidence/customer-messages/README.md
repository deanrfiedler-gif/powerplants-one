Browser screenshots are written to ignored `tmp/customer-messages-captures/`; after a passing run, the validated PNGs are copied to this evidence folder.

Earlier attempts are retained as limitations, not hidden: the first private database URL failed the local password guard; this was corrected. PostgreSQL's default lock allocation caused reset to fail with `out of shared memory`; unchanged main at `1402c87b` reproduced it. Increasing only this private cluster's `max_locks_per_transaction` to 1024 removed that reset error. Intermittent 3-second connection timeouts occurred in earlier S2/S3 runs; subsequent complete S2/S3 runs passed without changing application deadlines. A later main comparison initially lacked the repository font asset and could not establish a connection-timeout comparison; its original public assets were then restored. No unresolved timeout is labelled an unrelated product defect. A duplicate M2 preparation in the new test, two overbroad/wrong-name browser selectors and an HTTP assertion that incorrectly expected a reviewer without switch duty to have it were corrected. One later full browser run passed seven scenarios but hit Windows `UNKNOWN` opening a tracked queue capture for writing in B01. Capture output was moved into ignored temporary storage before copying validated artifacts; this is recorded as a capture-write failure, not an unrelated product claim. Studio's reference allowlist excludes `tests/`, so bindings reference this evidence document and its test links.

## Differences from the accepted compositions

- The rail retains **Sales Inbox**, as requested. The shared Email menu adds Customer messages beside Inbox. EC-01's unbuilt compose, Sent Items, correspondence views and linked-to groups are not fabricated. Personal mailbox status appears only on Inbox.
- Actual shared-shell icons, navigation and available actions replace the drawing's icon placeholders and story badges. Phone records retain the current shell's bottom navigation; the 48 px main action sits above it. The record retains Message/Facts/History tabs and a secondary More section as well as header More. Current shell Previous/Next visibility at 320 follows its shared behavior. The 1024 capture retains the current expanded rail rather than the accepted icon rail; the secondary menu collapses. Phone rows are taller because they retain full state, source and timestamp facts.
- The register uses shared table typography, borders, state chips and horizontal scrolling. It omits decorative selection boxes and bulk/menu controls without defined commands. Search, class/customer and prepared-on-or-after date filters operate on the disclosed candidate window, rather than the drawing's Last 30 days preset. Clear/Refresh and explicit simulation/coverage wording are visible. The phone filter uses native select/date fields rather than the drawn preset lists; the owner/customer-assignment checkboxes are not exposed. Sent remains neutral and explicitly simulated; the drawing's green Sent chip is not treated as delivery evidence.
- Native subjects, synthetic names, dates, counts and content differ from the drawing's ten-record story. M1/M2 are implemented; M3/M4 render only when readable records exist. There is no fabricated M4 example or new approval flow.
- Bound Supply Demand links and quantity/unit evidence replace the example work-order link, unsupported line counts, tracking URL and template publisher facts. Record headers retain the exact stored subject, including its source prefix. Snapshot Back/Open full record/Refresh controls replace the drawing's floating toolbar. Supporting phone source facts are under Facts/More so the exact email remains prominent. The left column labels the bound record owner as Message owner; the follow-up handover exposes its returned status, without inventing current assignee, due time or task instructions. History uses a numbered evidence list rather than the drawn timeline geometry.
- Confirmation uses the shared dialog/sheet, plain restated recipient/subject/template/sender/content check, an editable note and stacked shared buttons rather than the drawn fixed-check badges and desktop button arrangement. The full hash is shown in confirmation; preview abbreviates it with the full value in its title. Explicit simulation and recheck wording makes the sheet taller. Withdrawal and reconciliation require the existing API's reason.
- Message classes uses the shared read table and accessible switch-role buttons with current version information, rather than the drawing’s compact status/menu cells. Company selection and Refresh are explicit; the latest recorded change’s actor, time and reason are shown, but no unsupported full class-history endpoint is invented. Only available classes are shown. No template editor is introduced.
- Template management is absent on the integrated main base. Its handover is explicitly unavailable; stored version/hash remains visible. The source record and follow-up handovers use existing routes.
- Queue refresh is explicit; no pull-to-refresh claim. Phone held/failed/unknown records and classes are shared-pattern adaptations because the source has no corresponding record frames. No 200% zoom, physical-device, screen-reader or owner acceptance test was executed. Business AT-25/AT-36 acceptance and broad unrelated suites were not executed.
