## What the native checks cover

Five connected views and their provenance chips; counts opening exactly their contributing records with context restored on return; search narrowing with an explicitly selected out-of-result record kept visible; the eleven distinct outcomes in the record snapshot; refusal of a review date with no recorded basis; refusal of review completion while a commitment has no disposition; a completed review retaining three open obligations while every other outcome is unchanged; linking an existing case instead of duplicating it; the full prepare → submit → return → correct → resubmit → accept referral journey across two roles; training applicability flagging and the five separate training states; customer-identity isolation across records, search, counts and the filter option list; an MA-05 renewal link that leaves the agreement source byte-identical; a CRM handover submitted with a lost response, recovered without a duplicate opportunity, then reconciled from Unknown to Accepted; the chronological history grouping; a source change that retains a completed review; a failed save that keeps the form entries; partial, failed and empty source results with counts that never imply an empty workload; keyboard navigation and focus return; 44px touch targets and no horizontal scroll at 390px; export/restore into a read-only role; and preservation of a malformed stored session.

## Defects found and fixed in this session

Each was found by inspection or by a check in this session and fixed in the sources before the final run.

1. **Duplicated history entries.** The History view listed each referral, training and commercial event twice — once from the record timeline and once from the item's own history. The record timeline is now the single chronological log; item history stays in each item's drawer.
2. **Counts unaffected by the source scenario.** Summary counts were computed from the full model, so a partial read showed complete-looking totals and a failed read showed no tiles at all. Counts now describe the records actually loaded, show `—` and disable the tile when the read failed, and say "loaded records only" on a partial read.
3. **Stale dialog error text.** A new dialog could show the previous dialog's error via `textContent` on the hidden error region. The region is now cleared when a dialog opens, and a check asserts it.
4. **Duplicate-check candidates depended on typed text.** Relevant existing cases were only listed when wording happened to match. Every case recorded for the customer is now listed, ranked by equipment, growing area and wording overlap, alongside the record's existing owned actions and concerns, with an explicit statement that wording alone merges nothing.
5. **Worklist column balance.** The Next action column was too narrow for its date, due state, provenance chip and next step. Column widths were rebalanced at all three breakpoints.
6. **Phone review reachability.** The preparation briefing is long, so a phone user had to scroll it all to reach the capture form. A Jump to review capture control was added at narrow widths, without reordering the DOM.
7. **Duplicated wording.** The rating note repeated the "not assessed" statement, and the preparation panel's "Previous customer feedback" heading implied earlier reviews that do not exist. Both were reworded.

## Limits

* No application behaviour was tested, because none exists. There is no CR-05 route, schema, service, permission rule, adapter or migration.
* One browser. No screen-reader pass, assistive-technology testing, contrast-measurement tool run, zoom or reflow testing, cross-browser run or device testing.
* Two viewport widths: 1440×960 and 390×844.
* Preview roles are presentation controls. No authentication or authorisation was tested because none is implemented.
* The demonstration date is fixed at 16 September 2026; overdue and due-today states are relative to it.
* Six synthetic aftercare records across two customers. No performance or scale claim is made.
