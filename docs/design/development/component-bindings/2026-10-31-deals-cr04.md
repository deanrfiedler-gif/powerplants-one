# Deals CR-04 consumer bindings

<!-- versioning: git; committed history is authoritative -->

Owner: Dean Fiedler. Implementation: PR #699. Application review pending. [Accepted design](../../../decisions/deals-figma-design.md#acceptance--24-october-2026); [page contract](../pages/route-sales-opportunities.md). This fragment extends consumer bindings without editing the frozen catalogue manifest or shared CSS page lists.

## sales-board

Five 228 px stage tracks contain 212 × 264 px cards at 1440. Values and counts use the same permitted page. Native individual stage commands retain expected versions, refusal feedback, recovery and keyboard alternatives; closed records do not drag. The phone Board keeps stage navigation through the existing control.

## sales-table

The Grid export remains available from its catalogued module and delegates to the shared register consumer. Selection and settings stay fixed at 44 px. Columns can be shown, ordered and resized; the Deal column remains first. Phone List renders only its compact rows, avoiding duplicate interactive records.

## forecast

Month lanes group native stages and state accurate known-value and unknown-count subtotals. Brisbane calendar dates use the server observation. Undated and later buckets retain every returned record. Tablet and phone lanes scroll within the workspace.

## register-table

Deals uses RegisterTable and RegisterChip with a screen-reader caption identifying the result-page denominator, sort order and interaction. Selection, hover, scrolling and fixed columns use the existing shared table patterns; unknown values are never coerced to zero.

## dialog

Native stage/outcome editors remain modal and retain command/version recovery. Add deal embeds the native creation form with the same controls and guarded save intent. Snapshot and selected-list panels remain non-modal; sequential opening and focus return are explicit.

## drawer

Filters retain supported criteria, sorting and page-size controls, with browser URL context. Compact phone search/filter enters the same drawer. Expected close awaits the separately claimed, unmerged #790 design.

## menu

View options retain sorting/density. Column settings expose checkboxes and keyboard ordering. Stage menus retain collapse; More contains export and retained review/help controls. Pipeline settings and rotting remain labelled proposals. No bulk stage operation is introduced.

## read-state

Loading uses neutral shared-register placeholders without invented stage names or counts. Empty Board guidance overlays the native empty lanes; no-match List guidance follows its column headers and can clear the retained filter context. The snapshot uses exact native estimate, issued quotation and handover sources. Each bounded section distinguishes complete, partial and unavailable, preserves source versions and retries failed reads. Advisory conditions are review prompts, never new transition gates. A new query or revoked read clears selection and stale export authority.

## application-shell

The labelled Sales rail and current shared top bar remain authoritative. Tablet comparison uses the existing collapsed-rail control and preserves user preference. The shared phone view sheet, search/filter entry and Sales bar support the 390/320 compact List; Add deal floats above the bar.
