Dean asked for the complete refined UI page set of the Projects module to be drawn in Figma in the new private file "PPO - Projects module (proposal)", inside the accepted shell chrome and on the page template adopted for the Sales file, and recorded in the repository. The work ran from 9 to 10 November 2026 in fourteen batches, one scope page each: Projects register and Pulse, Initiation, Project record, Programme and baselines, Delivery readiness, Variations & obligations, Risks & issues, Subcontractor packages, Site assurance, Stakeholder updates, Acceptance & closeout, Field work and insights, Interaction states and Administration. The [proposal record](../decisions/projects-module-refined-ui-proposal.md) (PPO-PROJECTS-REFINED-FIGMA-PROP) holds the sources, the conformance declaration per scope area, the inventory of 248 frames with node IDs (234 sheets: 139 desktop including the interaction-states board, 33 dialogs and panels, 31 states, 16 tablets, 15 phones of which one is at 320; and 14 notes cards), the rules applied including the short reference form of PPO-REFERENCE-NAMESPACES-DEC per Dean's Addendum A2, the assumptions and proposed departures A1 to A92, the verification and the audit with a recommended order and the coverage of scenarios S-01 to S-37. The accepted shell components, kit, 101 icon stand-ins, tablet and phone chrome and the 66 "PPO colour" variables were rebuilt from the Sales file by script because the Plugin API cannot copy nodes across files. The file's link is not recorded here (ADR-0050, ADR-0053).

Checked: every sheet rendered and inspected after its batch; the structural pass found 248 frames, 4,234 one-line register cells and no issue; the position audit is clean on every page after three slot collisions were re-placed; the contrast proof computed from the colour variables on ST01 has no failing pair; wording scans found no score, percentage or index of health, readiness or risk. Repository checks run for this change: `python3 scripts/build_status.py --check` and `python3 scripts/check_foundation.py`. Not done: design acceptance (Dean's), the named version (Dean saves "PPO - Projects module (proposal) · 10 November 2026 · batch 14"), the register and guide updates that follow acceptance; no application code, route, migration, permission or deployment. Every record, person, value and date shown is synthetic.
