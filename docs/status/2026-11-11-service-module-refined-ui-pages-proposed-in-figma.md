title: Service module refined UI pages proposed in Figma
date: 2026-11-11
---

Dean asked for the refined UI pages of the Service module (the "Service operations" workspace) to be built in the new private Figma file "PPO - Service module (proposal)", inside the accepted shell and to at least the standard of the Sales module file, so that Service has one consistent, reviewable design set before any page is built. The [proposal record](../decisions/service-module-refined-ui-proposal.md) (PPO-SERVICE-REFINED-FIGMA-PROP) claims the work while the build is in progress. It holds the sources, the nine-field conformance declaration with the ownership of each scope, the rules applied, assumptions and proposed departures A1 to A42 (among them the 12 px collapsed strip as found, the separate technician phone bar, the derived work-order stages, the proposed Time & labour review page, the incident classification words and the story reconciliations of Addendum A3), what is not drawn, and the open questions. The first half of the build is drawn: My jobs, Job packs, Appointment detail, Schedule, Work orders, Service requests, Inspections, and Incidents and actions. Each page has desktop sheets at 1440, dialogs and panels, states, tablet at 1024, phone at 390 and 320, and a notes card. The second half, the sheet inventory with node IDs, the verification and the audit follow in this record. The brief's ten questions were answered by their stated defaults under Dean's standing instruction and can be reversed. The design is a proposal: Dean has not accepted it and no named version is saved yet. The file's link is not recorded here (ADR-0050, ADR-0053).

Checked: sheets were rendered and read during each batch and the defects found were corrected; the layout pass has run on the Incidents and actions page. Repository checks run for this change: `python3 scripts/build_status.py --check` and `python3 scripts/check_foundation.py`. Not done yet: the second half of the build, the layout pass, structural pass and position audit on the other pages, the contrast table, the story, capability, authority and offline scans, and the audit. Not in scope: prototype links, a person's keyboard, screen reader, zoom and device review, the design register and per-route page guidance (a separate reviewed change), and any application code, route, migration, permission, MYOB or Customer messages integration. Every record, person, value and date shown is synthetic.
