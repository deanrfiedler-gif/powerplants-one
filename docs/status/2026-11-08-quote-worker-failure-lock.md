date: 2026-11-08
---

Prompt X in [draft PR #872](https://github.com/deanrfiedler-gif/powerplants-one/pull/872), owned by Codex and based on main `1672c062981402037355fb9d813dbedabd87cfbb`, adds the workspace `FOR UPDATE` as the first statement of the quote worker's failure transaction. It closes the pre-existing gap in [#866's retained writer inventory](../testing/evidence/estimate-review-window-main/writer-inventory-v3.md#follow-up--8-november-2026-quote-worker-failure-lock). This supports EST-03/07/08 and the existing [exact-output recovery contract](../contracts/estimating-e1.md#exact-output-and-recovery). No currently observable response defect is claimed: release detail reads the job once; the review queue maps Running and Failed to Output pending.

The job's workspace ID supplies the lock. The existing Running/lease-token compare-and-set, error code and attempt insertion remain unchanged. Failure deliberately does not recheck authority, so revocation still records Failed. Claim, success, `QuoteWorkerInterrupted`, lease duration, grants, dependencies, schema and APIs are unchanged.

The failure transaction takes workspace then job, matching claim and success. Its predecessor transaction has already committed or rolled back and released its connection. The caller audit on this main found `retryQuote` from the HTTP render route, `runPendingQuoteJobs` from the document/demo workers, `prepareOwnerDemo`, and the estimating/E2 cost-basis restart scripts. They invoke the worker outside an enclosing workspace-locking transaction. Existing success already obtains that lock on its own pool connection; this adds no new enclosing-caller wait of that kind. This is a bounded lock-order argument, not a claim about every possible future caller or unrelated writer.

The three new database proofs passed on disposable PostgreSQL 16.15 in 23.022 s. The ordering proof observed `Lock/transactionid` after 11.7 ms with exactly one worker blocked by the reader's SHARE lock; the job remained Running at attempt 1 with only one Claimed row. After release it became Failed with `DraftRenderFailed`, cleared lease fields and exactly one Failed row for attempt 1. The other proofs revoke live preparation grants in `afterStore`, and use a native reclaim followed by `QuoteWorkerInterrupted` to prove the old failure preserves the complete new job row and its two Claimed attempts. Their renderer is explicitly synthetic and proves storage/lease behaviour, not valid rendered PDF output.

As a negative control, the same three proofs ran in a detached checkout of main `1672c0629` with unchanged runtime source: ordering failed because no worker waited on the reader (0, expected 1), while revoked authority and lease reclaim passed. This distinguishes the new exclusion guarantee from existing failure and lease semantics.

Additional validation passed: ten existing non-renderer E1/DR01 cases in `estimating.test.ts` (61.305 s), all four `estimating-review-locks.test.ts` proofs (26.732 s), and `npm run check` (Studio coverage, full lint, typecheck, 1,437 unit tests and production build). Foundation, prototype, naming, status-source, migration and 44 documentation tests passed. The unchanged existing test files and one-statement runtime diff were verified against main. Cloud setup succeeded with Node 24.21.0/npm 11.19.0 and database ready, browser unavailable. Full `estimating.test.ts`, `quotation-release.test.ts`, `p12-recovery.test.ts`, real-renderer/restart and browser suites are not run locally because they need the unavailable browser; they remain for GitHub CI. Existing tests and timeouts are unchanged. The pre-existing line-273 P01–P11 browser failure is outside this task and must be classified if it recurs on the ready head.
