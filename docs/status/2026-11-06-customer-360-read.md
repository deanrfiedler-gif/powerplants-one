[PR #863](https://github.com/deanrfiedler-gif/powerplants-one/pull/863) batches the Customer 360 native readers and reuses exact scoped capability checks within one request. Native authority, first-100 candidate windows, DTO ordering, error semantics and the final root recheck are retained. The implementation is a Codex decision under the standing order; no PR merge or deployment is performed.

The representative compiled workspace read fell from **1,627 to 85 statements**, with wall time **2,965.422 → 1,702.101 ms**. Summed PostgreSQL duration was **1,543.049 → 2,567.298 ms**. A larger fixture exercising candidate and revision limits fell from **5,530 to 112 statements**, with wall time **9,017.608 → 3,537.297 ms** and summed database duration **3,957.575 → 3,811.026 ms**. These are single warmed samples on unchanged synthetic business data with both servers and PostgreSQL pinned to one CPU. Summed query durations can overlap; they are not database CPU measurements.

The [Customer 360 delivery chapter](../delivery/cs-native-completion-handover.md#customer-360-read-batching--6-november-2026) describes the design. The [execution record](../testing/evidence/customer-360-read/README.md) retains the raw-DTO and JSON equality proof, final source hashes, same-data measurements and individual main-comparison results. The review follow-up full check passed all 1,422 unit tests and the production build. On the reviewed head, both equality tests and 14 existing Customer 360 database cases passed. The selected 205-case regression run passed 159 cases; all 46 failed cases also failed on clean main. Two additional aftercare rendering failures also reproduced on main.

Setup reports PostgreSQL ready and the browser unavailable. Local browser suites are **not run here; left to GitHub CI**. Claude’s one independent review found no must-fix defects. Follow-up work adds non-vacuous Finance equivalence, discloses the shared Activities adapter, bounds post-cap diagnostics and reduces Customer 360 batches to 50 after a 1,462.378 ms statement was measured. Re-measured maxima are 726.117 ms and 689.889 ms, below one second. All three equality cases and the exact-cap unit proof passed. Follow-up database suites passed 150/153; all three rendering failures reproduced on clean main. HTTP passed 92/115 on both branch and main with all 23 failure messages matching. CI results and confirmation of findings 1–4 belong in the PR evidence comment; no second full review or merge is claimed.
