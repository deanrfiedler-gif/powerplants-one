The Service module design set that Dean asked for is now complete in the private Figma file "PPO - Service module (proposal)", so the whole Service operations workspace can be reviewed as one consistent proposal before any page is built. The [proposal record](../decisions/service-module-refined-ui-proposal.md) (PPO-SERVICE-REFINED-FIGMA-PROP) is updated in place. It now holds the full inventory of 288 sheets on 17 pages with every node ID, assumptions and proposed departures A1 to A55, the verification results, the audit of 11 November 2026 and the named version Dean is asked to save. The second half added Field team, Service review (reports, customer response, findings, escalations), Time and labour review, Service agreements, Maintenance, Warranty, the Service extract of Insights, the interaction-states sheet with page states PS01 to PS12, ten administration sheets and the Service operations flyout. The audit applied eight corrections in the file (among them the removal of sync wording from technician phone screens, a "cleared" assertion on one appointment state, and a green button that failed contrast) and proposes five refinements, four gaps, the innovation candidates and a review order. The design remains a proposal: Dean has not accepted it and no named version is saved yet. The file's link is not recorded here (ADR-0050, ADR-0053).

Checked: the structural pass and position audit ran clean on all 17 pages; the node ID and size of every sheet were read back from the file and match the inventory; the brief's minimum counts are met; the contrast table is computed on ST01 from the PPO colour variables (lowest text pair in use 5.29:1); a text scan of every sheet found one date style, no banned assurance words outside the rule's own statement, no amount outside a labelled Finance figure or the proposed goodwill limit, and a connection state in words on every technician phone sheet; the brief's scenarios S-01 to S-36 each name sheets that exist. Repository checks run for this change: `python3 scripts/build_status.py --check` and `python3 scripts/check_foundation.py`. Not done: no prototype flow is wired; no person's device, keyboard, screen reader, glove or 200 % zoom review is recorded; not every sheet was read by eye and the story scan does not prove every row value against the dataset. Not in scope: the design register and per-route page guidance (a separate reviewed change), and any application code, route, migration, permission, MYOB or Customer messages integration. Every record, person, value and date shown is synthetic.
