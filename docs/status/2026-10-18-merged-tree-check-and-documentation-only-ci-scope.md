title: Merged-tree check and documentation-only CI scope
date: 2026-10-18
---

Following Dean's "Proceed on that basis" on 18 October 2026, CI gains a merged-tree check and a documentation-only scope for the heavy suites ([record, section 4](../decisions/merge-conflict-reduction.md), PPO-MERGE-CONFLICT-DEC). Workflow files and `scripts/ci_scope.py` only: no application code, migration, permission or parent ID changes, and branch protection is untouched.
- **Check merged tree against main** (`.github/workflows/merged-tree.yml`) merges the pull request head into the current `origin/main`, then runs the foundation, prototype, naming, migration-number and status-fragment checks and `npm run typecheck` (the type check is skipped for a documentation-only change). The job name is stable and the workflow has no path filter, so Dean can add it as a required check once it has run on one pull request. A green result is as fresh as its last run; nothing reruns it when `main` moves, so rerun it before merging if other pull requests have landed.
- **Documentation-only scope.** Ten workflows (application, compiled browser, CRM refinements, Email Calendar journey, Estimating E1, Products and the four quotation workflows) start with a `Change scope` job and skip their database and browser jobs when every changed path is Markdown, CSV or text in a prose folder, a root documentation file or a `db/reservations` note and no source or test names it. `docs/design/**`, `docs/reference/**` and test evidence are never scoped out, because the application and tests read them. Any other event, a push to `main` or a fault in the scope job runs everything.
- **Required checks.** The seven required names are unchanged and each still belongs to one job; the six that can be skipped (all but Check documentation foundation) report as skipped, which GitHub counts as passing for a required check. Concurrency groups that cancel superseded pull request runs were already on every pull request workflow, so none were added.
- **Branch protection as read.** A read-only call on 18 October returned `strict: false` with those seven contexts, so "Require branches to be up to date" was already off: until the merged-tree check is made required, nothing checks the merged result before a merge.
- **Checked:** every workflow parses, every `needs` resolves, the seven required names are unique; the classifier passes its 32 self-test cases; it marks 10 of the 39 most recent pull requests documentation only; the five documentation checks pass on this branch.
- **Not verified:** a real documentation-only pull request through branch protection (the skipped-required-job behaviour rests on GitHub's documentation); the merged-tree job and the sparse checkout on a runner until this pull request's own run; no `actionlint` was available, so expression syntax was parsed, not linted. Not done: scoping design-register pull requests, `dependency-audit`, `development-register` or pushes to `main`, and a merge queue.
