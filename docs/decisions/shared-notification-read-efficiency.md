# Shared notification read efficiency

Owner: Dean Fiedler. 4 October 2026. Bounded synthetic implementation choice under PR #344; owner and deployment acceptance remain separate. Continues [ADR-0041](ADR-0041-sh-platform-coordination.md).

The broad development-browser run on `9519f1c` found the notification bell still loading after the page behind it had resolved the same new notice. The current inbox resolves up to 200 events serially through the full authoritative Activity reader, repeating that read for every historical event of the same Activity. Its source is unchanged from refreshed main. No notification content is missing in the retained page capture; this is distinct from the earlier Engineering focus race, whose new regression passed in both broad browser modes.

Resolve each distinct Activity once per inbox request, through the existing `readActivity` authority checks, and process at most four notices concurrently. Preserve event order, identities, source versions, personal states, current source details, partial/unavailable semantics and independent owned obligations. The small concurrency bound leaves headroom in the existing pool; it is not a new worker, service, global cache or permission grant. The map is discarded after each request. Later requests and direct notice reads recheck current permissions and source content. A rejected source remains rejected for all its events in that response.

Keeping the serial duplicate reads makes response cost grow with history rather than distinct current sources. A cross-request cache would require new invalidation and authority guarantees. Unbounded parallel reads could crowd out other work. Neither alternative is adopted; connection limits and all deadlines remain unchanged.

The responsive browser fixture also visits each of its five pages once and resizes the mounted page through all seven existing widths, then checks the same six review perspectives. It retains all layout, readiness, screenshot and interaction assertions, both browser projects and its original 180-second deadline. This exercises live reflow while avoiding thirty redundant whole-page navigations; it neither splits nor skips coverage. Functional evidence, source review, visual acceptance and deployment are recorded separately in the [execution ledger](../testing/evidence/quotation-supply-followup/README.md).

The `483fd66` development run exposed an additional fixture boundary at 768px. My Work intentionally mounts a fresh overview when crossing its native 780px phone boundary and re-reads current data. The resized matrix had observed only initial navigation, leaving this new read inside its five-second render assertion. A held real successful GET reproduces the same busy-state failure. Reuse the existing 15-second My Work transport observer before a breakpoint-crossing resize, then retain the original five-second render assertion and 180-second matrix bound. Same-layout resizes wait for no invented request. Both crossing directions, delayed exact responses, unrelated responses and refusal are regression covered. No runtime cache, change to current authority, retry or deadline extension is adopted.
