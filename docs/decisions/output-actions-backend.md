# DK-03 controlled output actions

Owner: Dean Fiedler. Decision: 13 October 2026. Backend implementation authorised; independent review, business acceptance and deployment remain separate.

This increment continues the read-only register in PR #468. It retains DK-03, DOC-01–DOC-06, OUT-09/OUT-10 and AT-07/AT-13/AT-20/AT-36. Job Pack and Service Report services retain review, issue, withdrawal, response and render authority. The shared API forwards explicit native commands and original operation IDs; it does not introduce a universal approval rule. Service Report amendment remains its native successor process, not a new withdrawal command.

The repository already uses PostgreSQL, transactional original-operation receipts and durable render workers. These are retained; no new technology, provider, dependency or permission is selected. A separate delivery engine or reusing audit prose as a mutable delivery ledger would duplicate authority or lose concurrency constraints. Migration 0090 therefore adds only two empty tables: immutable synthetic distribution attempts and append-only state events, bound to an exact native issue and recipient. No existing issue, grant or user is rewritten. The existing outbox allowlist gains three distribution events, preserving all earlier kinds. A native pack-event guard prevents bypassing unresolved DK-03 attempts; existing native simulated sends also block replacement attempts.

Distribution is deliberately **Synthetic**. Prepare verifies the retained original bundle, current issue applicability, permitted audience and expected parent version. An attempt begins Prepared. A simulation records SimulatedSent, SimulatedNotSent or OutcomeUnknown. Only OutcomeUnknown can be reconciled, additively, to SimulatedSent or SimulatedNotSent. These are simulation observations, never provider delivery evidence. Prepared, unknown and simulated-sent attempts prevent replacement for that exact recipient/issue; a new attempt is permitted after a recorded simulated non-send. An abandoned Prepared attempt can explicitly record SimulatedNotSent. No retry sends anything externally. Real sent/delivered timestamps remain null.

Each event has its own original operation, expected attempt version, actor, reason and evidence. Current native issue permission is rechecked before receipt replay and history reads. New distribution and simulated send require current applicability and exact bytes. Recording non-send/unknown or reconciling an already unknown outcome remains possible after supersession or withdrawal: historical reconciliation describes the old attempt and never reactivates it. Permission loss still refuses access. Database guards enforce native parent/recipient/hash binding, event order, terminal states and one unresolved/sent attempt per recipient. Transactions commit evidence, receipt, audit and outbox together.

Issue recovery uses the original native render job. It neither allocates a replacement issue nor regenerates an already issued missing file. Worker recovery after stored bytes but before finalisation is tested against the retained original. Responses remain native exact-presentation commands; no acknowledgement is copied to a successor. Live providers, broader output families, UI integration and DK-06 template administration remain separate.
