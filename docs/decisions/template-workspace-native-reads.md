# Template workspace native read projections

<!-- versioning: git; committed history is authoritative -->

Decision author: Codex under Dean's standing order, 31 October 2026. Owner: Dean Fiedler. Implementation and independent review in progress; this is not owner acceptance.

The accepted [DK-06 page](template-management-figma-design.md) requires readable scope, actor and version labels, ordered evidence and permitted choices. Preserve the unfinished branch's native read projections, with scoped choice endpoints for template sites and exact publications. Existing proposal, revision, publication, company/site, source-binding and command checks remain authoritative. No new technology, migration, capability, grant or dependency is introduced.

Use stored names and explicit version labels rather than UI-generated sample facts. Re-read the displayed page window on continuation so earlier rows cannot survive a failed current-authority read. Order immutable revision/review history by native revision/command sequence rather than random UUIDs. Signed continuation context changes with the ordering contract. Publication and site assignment remain distinct OUT-09 decisions.

The alternatives were client-side directory joins, unbounded catalogues or presentation samples. Scoped native projections keep evidence within the existing permission boundaries and preserve bounded reads. Reversal is a reviewed change to these read projections and consumers; retained evidence and receipts are not rewritten.

The extra proposal-list guard inherited from the draft changed main's permitted-empty response. Automatic approval review initially blocked its removal. Dean explicitly approved restoring main's behavior on 31 October, and only that additional list gate was removed. Every candidate and returned record still passes the native scoped template/source checks; command authority is unchanged. Native database and page proof remain required.

Execution refinement: publication choice titles use the exact immutable published template name, because the native publication snapshot retains proposal metadata rather than revision body fields. Latest review and publisher names are resolved only after authorization and followed by context rechecks. On a failed current read, the UI removes dialog evidence while retaining only the original pending operation for unchanged reconciliation; it does not create a replacement intent.
