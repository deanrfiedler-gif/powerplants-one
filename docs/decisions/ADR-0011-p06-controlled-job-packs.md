# ADR-0011 — P06 controlled job packs

**Date:** 5 September 2026 · **Status:** Implemented and component-verified; publication evidence in the P06 handover. **Related:** issue #30, SC-06/14, DAT-07/11, OUT-09, API-C08–11, TR-04–07, EVT-04/05, PT-06/07/18/23 components.

Retain the TypeScript/PostgreSQL modular monolith and workspace transaction lock. Pack preparation is independent of dispatch readiness: a confirmed appointment and current authorised scope can be prepared and checked while dispatch is held. Final issue additionally requires current non-waivable authority, exact sources, current template policy and a complete set of individually identified recipient assignments. A successor scope Draft never authorises extra work.

Use Playwright **1.63.0**, already locked for testing, as an explicit runtime dependency with its matching Chromium build. One escaped semantic HTML snapshot supplies preview and A4 portrait PDF, with repeated identity/footer, page numbers, tagged output and outline requested. The Apache-2.0 licence and Node 24/Windows 11/Ubuntu 24.04 compatibility were checked against [licence](https://github.com/microsoft/playwright/blob/main/LICENSE), [system requirements](https://playwright.dev/docs/intro#system-requirements) and [PDF API](https://playwright.dev/docs/api/class-page#page-pdf). Chromium and bundled third-party notices remain applicable. No PDF/UA, assistive-technology or identical cross-machine output claim follows from the tagged option. Retained bytes, renderer/browser version and hashes establish actual output provenance. HTML is the accessible reading route; PDF receives visual and structural component inspection. Alternatives: PDFKit adds separate pagination/layout code; ReportLab introduces Python runtime/dependency ownership; a remote renderer adds an unnecessary service and confidentiality boundary.

The replaceable synthetic adapter uses a configured private absolute directory outside the repository. Exclusive atomic file publication, fsync, fixed generated keys, byte counts and SHA-256 retrieval verification retain fictional sources and output. P04 immutable PostgreSQL text evidence and receipts remain unchanged. No live SharePoint, upload, retention deletion, email, SMS or calendar adapter is enabled. Missing exact versions fail explicitly; no latest substitution. Published source/template bundles have no editor in this increment.

Issue first commits an idempotent render intent and owned recovery record. A worker claims that durable attempt; rendering and storage run outside the business transaction. An operation-specific write-once bundle preserves the original HTML/PDF/manifest even if database finalisation fails. Retry locates that bundle and verifies it before rechecking current scope, appointment, assignments, recipients, source/template policy and actor permissions. Only the final transaction creates the immutable issue, current pointer, recipient tasks, audit and outbox event. A 202/Queued/Generated/Durable attempt is never Issued. Attempt outcomes and safe failure codes are retained; no raw exception is disclosed.

Pack content revisions and check decisions are separate from issue/applicability/distribution events. Amendments immediately hold dispatch, retain prior issue and require fresh check/issue/individual acknowledgements. P05 schedule/assignment changes and cancellation invalidate real pack applicability in the same database transaction; issued bytes and prior responses remain. Current dispatch guard recomputes source authority and every active recipient's exact issue acknowledgement. P07 attendance/start is absent and remains an integrated dependency. Customer date agreement is unrelated to pack acknowledgement.

Technician access requires current record/file capability plus current assignment and exact recipient scope; coordinators have explicit preparation/check/issue authority. Output DTOs allowlist business fields and service-audience sources, including titles/attachment names/metadata. No internal financial notes, balances, account plans or generic serialised database rows appear in output. Receipt recovery rechecks current authority before returning original accepted evidence.

Additive migration 0006 and seed receipt 6 preserve earlier migrations, seed bytes, identities, grants/revocations, booking snapshots/reservations and receipts. New synthetic recipient resources avoid modifying immutable P05 resource bundles. Full PT/AT, independent review, owner acceptance and production readiness remain separate and incomplete. P09 reports/P10 Finance outputs stay at their existing contracts.

The file reserves its issue UUID/time before rendering, explicitly conditional on release; final immutable issue `issued_at` records actual release only after durable verification. This refines the general file-time contract: queued/generated files cannot honestly assert a future database commit time. Reconciliation retains the original reserved timestamp and bytes. All revisions are treated as material; no cosmetic-change bypass exists. ReviewRequired/Withdrawn events atomically create real P03 service-owner contact Activities with explicit unknown due dates, Site links and required recorded outcomes. They do not send communication or automatically complete on a new issue.
