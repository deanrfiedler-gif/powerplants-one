# Navigation consolidation

<!-- versioning: git; committed history is authoritative -->

**Owner:** Dean Fiedler · **Review:** Pending · **Decision date:** 8 October 2026.

Dean authorised implementation of NAV-02A through NAV-06 from the supplied NAV-01 audit of `4f883d145b18876840c5ce5522059c95448dc086`. Source-confirmed contradictions and browser results remain separate in the [implementation ledger](../testing/evidence/navigation/README.md). This decision implements repository navigation; it grants no business approval, production access or receiving authority.

The existing typed shell registry remains the authority for destination discovery, workspace ownership, capability policy, availability and route-parent resolution. Bounded contextual href helpers fix Survey Equipment and Acceptance Activity callers directly. Existing Customer/Contact URL-view selection is reused for Deal, Sales handover and Engineering record sections; estimate revisions retain their owning reader's membership checks. A universal routing framework was rejected because these defects require small corrections and clearer existing metadata, not new infrastructure.

Home retains `/work` when `activity.read` is present. Otherwise it chooses a declared permitted operational destination; personal My Work alone does not advertise seven departments. Ordinary Workspace selection lives in global More on desktop and phone. Development > Shell preview changes presentation only. Inspection review discovery requires `report.read` **and** `service.work_order.edit`; its existing per-visit scoped access checks remain authoritative. Discovery's stronger leave/recovery guard remains; other mounted dirty forms and preferences share pointer, touch, keyboard, router and native Chrome history review. Cancelling a workspace intent cannot save its preference.

The primary rail defaults to its established compact 76 px mode and expands to labelled 232 px mode. Its schema-checked preference belongs to the identity/browser, with a visit-memory fallback when storage fails. Navy `#242a37` is primary, green `#62bb46` remains a restrained brand accent, and semantic status colours remain. Roboto, logo and icons are reused. The 780/781 px shell boundary and 1200 px secondary-menu docking are retained. Sales phone destinations gain visible labels and Leads retains global Home/More/search/help. Service and Email duplicate header tabs are removed where the module already owns the same views. This is a proposed departure from retained shell r17, informed by theme r22; no issued source or baseline acceptance changes.

Actual ready-state screenshot inspection exposed squeezed My Work activity titles with both rails expanded. A bounded standard CSS container query moves supporting panels below Activities at the available-content threshold. Changing viewport breakpoints would miss rail width changes at a fixed viewport and alter unrelated module docking; a new layout dependency is unnecessary. The pinned Chrome runtime supports the existing CSS approach. Populated-row readability and actual captures validate this repair separately from owner/device review.

The existing header width rule hides ancestors on narrower desktops. A labelled 44 px Page hierarchy disclosure reuses the native popover pattern already used by CRM controls; it exposes all authorized parent links without changing header centring or adding a navigation framework. Escape restores trigger focus and route changes close it. Relying on title text was rejected because it is not a usable parent action on touch or keyboard.

Quotations offer URL-backed continuation through windows of 100 scoped estimates and an estimate-reference/title filter. Each quotation still passes its own exact-record guard. The UI explicitly describes the partial source; it does not claim a complete quotation register or universal record search. Reviewed/issued reports can open an existing exact scoped Finance handoff. Preparation is offered only for an issued source with existing `finance.prepare` authority; the receiving form rechecks source/work membership and requires deliberate source selection, account, allocation and independent recipient controls. Navigation creates nothing and changes no ERP authority.

Safe post-login return (F17/N30) is **deferred**. The gateway continues to refuse caller-supplied return URLs, preserving OAuth/session controls. Its fixed post-authentication destination becomes permission-aware Home. A future short-lived server-bound intent requires a separate reviewed security design. New record-search adapters are also deferred until reader, scope, pagination and unavailable-source contracts exist. No grants, migrations, dependencies or modules are added. Native standalone sales orders, customer portal and Installation remain unimplemented; installation journeys use existing Project, Service and commissioning surfaces, and quotation conversion remains synthetic Supply demand rather than ERP order creation.

Functional proof, screenshot inspection, owner/device/screen-reader acceptance and deployment are recorded independently. No merge or deployment is authorised by this contribution.
