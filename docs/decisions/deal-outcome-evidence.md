# Explicit Deal outcome evidence

<!-- versioning: git; committed history is authoritative -->

Owner: Dean Fiedler. Date: 7 October 2026. Review: proposed implementation within the user-authorised Leads/Deals programme; business acceptance pending. Parent scope: CRM-03 / EST-01, CR-01, AT-02, AT-25 and AT-26. Programme contract: [lead-to-delivery continuity](../contracts/lead-to-delivery-continuity.md).

New Deal outcome forms require an explicit evidence choice. Quotation evidence compares the exact current issued revision, output hash and staff-recorded response. Won requires an Accepted response with the native response holds cleared; Lost requires a Declined report. The Deal still requires its existing stage and acceptance-evidence or structured lost-reason checks. Separate evidence is a deliberate alternative with a required narrative; it makes no claim about a native quote. Neither path converts scope, verifies customer authority or authorises delivery.

The original outcome event, receipt and Won handover-due record retain their existing roles. Migration 0075 adds an immutable companion for the selected evidence. Typed native keys and deferred evidence checks bind it to the same Deal, exact event, audit, receipt and publication. Application checks retain current access, the current quotation header/revision, latest issue and native response holds. The source is the immutable issued document: ordinary Deal stage progression after issue does not invalidate its evidence. ES-05 source hashes and successor rules remain byte-for-byte unchanged; this outcome command does not rerun an issue decision against a later Deal version. No new technology, capability, grant, seed or user is introduced. The existing PostgreSQL transaction is retained because the outcome and its evidence must either all commit or all roll back; a second lifecycle store or automatic Won inference would break that boundary.

An absent source property keeps the historical API payload and hash unchanged. Older outcomes are labelled historical narrative evidence; they are never backfilled with a guessed quotation. A subsequent response correction or issue does not rewrite the saved outcome or its evidence. Original recovery uses the retained source and current all-target permission, rather than requiring the current response to equal the original decision. New intent always compares current source facts.

The form freezes the reviewed comparison. Background refresh cannot silently advance the command to a different response. Denied refresh removes the displayed comparison and disables submission until an explicit permitted evidence choice is made. An uncertain command retains its original operation and can only be recovered; it cannot be replaced with a different evidence choice. Limited browser and database proof, human review and deployment are separate records.
