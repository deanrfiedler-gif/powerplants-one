Owner: Dean Fiedler. Date: 7 October 2026. Review: implementation verified with synthetic checks under the user-authorised Leads/Deals programme; owner acceptance pending. Scope: CRM-01–CRM-08, CR-01 / CR-05 and existing shared Activity, Project, Service and Maintenance scopes. Contract: [lead-to-delivery continuity](../contracts/lead-to-delivery-continuity.md).

Reuse an existing owned, dated Internal CustomerContact or RelationshipReview Activity for a reviewed new customer need. The live Activity graph requires Internal access and exact captured site context for Lead/Deal links; original Activity access class is immutable. A restricted Service, technical or completed source can therefore create a separate Internal Sales review Activity with an explicitly reviewed summary, owner and date. Its native links and exact original Activity/version are retained as source evidence; the original is neither reclassified nor completed. Project delivery, Service/aftercare and Maintenance/renewal remain source authorities. A reviewed follow-up does not establish qualification, warranty coverage, technical completion, a message sent or a customer commitment. Unqualified needs use native Lead capture; a Deal still requires the existing CRM qualification and initial-action controls.

The Activity owner explicitly selects an existing same-context Lead/Deal, or independently creates one through the native form and returns for a separate link review. Compare the exact Activity version/links and target version, customer/site context and current ownership/access. Preserve the original Activity owner, due date, state and native links. Linking adds the existing typed Activity relationship, advances its comparison version and records an exact audit/receipt/publication; it does not complete the Activity or transfer its ownership. An already linked Sales record is opened rather than silently creating a duplicate; a separate need requires a separate owned follow-up.

Known Organisation and Project customer anchors must match. Site-only sources do not imply a particular customer: native capture and the explicit link comparison must identify a permitted current site party. Lead customer resolution remains separate from captured context; incompatible captured Activity site context is refused, not rewritten. A disqualified/converted/archived Lead or closed Deal cannot receive a new continuation.

Native capture, link and any aftercare receiving acknowledgement save separately and retain actor-bound original recovery. A lost creation/link response cannot create a replacement intent. Current original-source and target authority governs link/review receipt recovery after later owner, source or lifecycle changes, including nested original-review provenance. Native creation receipts retain their own native authority even when source access is later lost. The original version and context remain in audit evidence. Existing aftercare CRM receiving still requires its explicit confirmed target; this continuation does not accept that handover automatically.

The existing PostgreSQL transaction, Activity links, audit events, receipts, command journal and native CRM forms are reused. Alternatives considered were another referral/lead store or automatically creating a Deal from delivery evidence; both would duplicate authority or infer qualification. No technology, framework, migration, capability, grant or seed is selected or added. Link review does not replace a Lead/Deal designated next action; the native Lead planning action can explicitly designate the retained linked review, while existing Deal initial-action controls remain unchanged. Issued reference snapshots and historical command payload/hash strings stay unchanged. Design review, owner acceptance and deployment remain separate from synthetic implementation proof.
