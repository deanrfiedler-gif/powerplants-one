## Bounded proposal

Use three online commercial journeys: customer context, owned opportunity follow-up and manual saved estimating/exact draft quotation. Keep a longer service tour optional and presenter-led in supported local mode. Assess five invited testers, three concurrent users and a two-week evaluation. Use fictional records; preserve existing IDs, issue bytes, operational source ownership and all 78 parent requirements.

Retain BP-02's preferred Azure Container Apps assessment, with managed PostgreSQL and protected synthetic document storage. This does not select a new application stack. The package compares the immediate local presentation with the later authenticated hosted form. Hosted document adaptation must preserve exact-content storage semantics; an untested generic file mount is insufficient.

| Alternative | Assessment |
|---|---|
| Local presentation/screen share | Available using the current supported local mode; no cloud bill. Good immediate walkthrough, limited independent access. |
| Separate local installations | Possible with per-computer setup and dedicated fixtures; more support/update work. |
| Office server/VM | Possible after real shared authentication and support setup; not a shortcut around local-only guards. |
| Managed Next.js host plus database | Viable alternative, but renderer, worker, private storage and remote identity still need implementation; compare if Azure account/support constraints rule out the preferred assessment. |
| Azure Container Apps + PostgreSQL | Best fit to assess under existing BP-02 direction; itemised budget and compatibility obligations documented. No subscription purchase or deployment selected. |

Do not make the synthetic identity adapter remotely accessible by changing bind addresses, hiding provider environment variables, rewriting trusted headers or adding a tunnel. Create a proper authenticated demo path and keep current local restrictions/test expectations. Each remote human maps to an individual server principal with reviewed Company A capabilities; no shared SYN Coordinator session.

P01–P12 remain in their existing order. P11/P12 remote-readiness requirements are not waived. The package does not invoke later application work, a customer portal, real ERP/SharePoint writes, corporate rollout or operational migration. D-020/D-022/D-023 remain open for actual identity, hosting and support arrangements. No new numbered ADR or parent ID is reserved while parallel implementation continues.
