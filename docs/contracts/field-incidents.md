# FI-06 incident API and data contract

<!-- versioning: git; committed history is authoritative -->

Owner: Dean Fiedler. Implementation contract; independent review and acceptance remain separate. [Architecture decision](../decisions/field-incidents.md).

GET `/api/v1/service/incidents` returns only permitted operational summaries, bounded to the latest 200 candidates. GET `/context?appointment_id=…` supplies permitted exact scope/equipment choices; adding `scope_item_id` and `asset_id` produces a current source hash. GET `/[id]` returns the permitted record/history/actions/evidence/outcomes. GET `/[id]/files?evidence_id=…` and `?output_id=…&format=pdf` recheck current scope/audience and original hashes. All responses disable caching.

POST `/api/v1/service/incidents` accepts schema version 1, an unchanged operation ID, incident UUID, action and reason. Existing records require `expected_version`. Commands: create, save, submit, triage, review, action, evidence, accept_action, accept, close, reopen, rebind, link and adopt_assignment. Create additionally binds appointment, exact scope/equipment and preview hash. Actor and reporting time are server-derived. Generic receipts/audit/outbox contain no factual or restricted reasons; protected events retain the original attributable reason. Repeated operation payloads replay one receipt; changed reuse conflicts.

Migration/seed 0056 adds incidents, immutable bindings, coordinated actions, immutable original evidence, retained events and controlled output manifests. It extends typed identities, audit/outbox categories and five explicit capabilities. It preserves installed SQL/seed bytes, 0051/0052 reservations and all prior identity/grant rows. Seed 56 adds nine grants to three existing local fictional identities only, retaining their scopes. It adds no user or hosted tester authority.

Restricted details and Restricted evidence are visible only to the original reporter under current incident scope or an explicit incident.sensitive reader. Ordinary permitted readers see operational facts and minimal hold context. Sensitive review commands additionally require incident.sensitive. Every current command duty is rechecked before duplicate receipt disclosure. Source bindings, action acceptance and historical raw snapshots are not exposed through generic Activities, search, lists, counters, audit reasons, output or errors. No general incident search/export adapter exists; the register and controlled outcome are the supported surfaces.

An action creates an actual RestrictedService Activity with a fixed minimal source link. Its operational instruction remains on the incident. Perform and complete work through Activities/My Work. Activity detail reads its stored incident-action association and offers a return link only after current incident read/assignment checks; neither labels nor summaries create that relationship. Reassign there using its existing versioned command, then explicitly adopt the exact Activity version in the incident; this clears prior action acceptance. Record a new correction file for the new owner. No direct client database edit or task-completion shortcut exists.

PNG is bounded to 2 MiB and the existing strict PNG validator; plain UTF-8 text to 64 KiB. File ID, original bytes, SHA-256, length, media type, audience, actor, time and incident/action association are immutable. File failure rolls back the evidence row. Storage orphans can remain after a failed database transaction but never constitute accepted evidence. Missing original files prevent acceptance. No JPEG/WebP, camera service or general attachment repository is introduced.

Each submitted unassessed incident conservatively holds its exact scope. Independent triage records assessment, priority, owner/due and basis. Existing holds require independent closure. Correction/rebind/reopening withdraws acceptance; reopening preserves original output bytes. Closure requires current sources, known assessment, completed Activities, independent action-evidence acceptance and independently accepted exact incident content. Linked inspection defects must separately complete their own correction/retest/acceptance. A closed incident grants no general work permission.

Readiness and Start evaluate all incident holds applicable to their appointment scope. Inspection evidence and corrective retests remain possible under an incident hold while inspection release checks the exact occurrence. Existing scheduling-policy, pack, assignment and FI-05 controls still apply. An arriving hold changes current authority without cancelling attendance or editing timer history. P07/P08 factual capture retains ReviewRequired attribution where applicable; delayed offline Start revalidates current server holds. Incident operations are online only.

The scoped Internal outcome uses the existing exact HTML/PDF bundle mechanism with internal kind IncidentOutcome and a separately named incident template. This is not a new parent output requirement or a commissioning approval. It binds policy, exact review/source, scope, accepted actions, operational evidence, exclusions and remaining work. Restricted source facts remain protected. No notification, external distribution, regulatory report, equipment command, appointment/work-order/project/customer/Finance completion is available.

Compatibility: pre-0056 populated-upgrade proofs have no incident storage and no incident authority. An installed 0056 with missing storage fails closed. Rolling back to an application that lacks incident enforcement cannot safely keep incident-enabled writers active; preserve data and use a forward repair or stop writes. Deployment and rollback are not performed by this contribution.
